# Readable Python

Match the requested behavior and the user's demonstrated experience. When course examples or existing code are available, follow their terminology and conventions without fabricating a personal style.

- Understand the inputs, outputs, constraints, and existing behavior before refactoring.
- Prefer concrete names, explicit intermediate values, and short methods with a clear purpose. Keep abstractions required by the task; avoid adding unrelated frameworks.
- Use familiar Python and pandas operations. Prefer an ordinary loop when a compressed expression would be harder for the learner to explain.
- Comment on reasons, assumptions, or real edge cases. Do not invent debugging stories, mistakes, or development history.
- Preserve correctness and consistent formatting. Do not add deliberate errors, pointless repetition, or cosmetic irregularities to imitate a person.
- Run representative examples and relevant edge cases. Explain behavior changes and limitations.
- For coursework, provide concise explanations and questions the learner can use to check understanding. Do not claim independent authorship or promise to evade AI detection.
